# Aelin 多平台视频/内容接入与日记沉淀方案

> 文档目标：将「输入 URL → 内容理解与总结 → 写入 OpenViking 日记」做成稳定、可扩展、可追踪的后端能力。

## 1. 要解决什么问题

当前能力在文本检索与追踪上已经较完整，但在「视频内容理解」上仍有明显短板：

1. **视频语义缺口**：很多 URL 是视频内容，不能只靠网页摘要理解核心信息。
2. **记忆污染风险**：无字幕时若直接用简介文本写入长期记忆，质量不稳定。
3. **主链路阻塞风险**：音频提取与 ASR 是重任务，不应阻塞 chat 主流程。
4. **可观测性不足**：缺少标准化状态机与质量评分，难以判断总结是否可信。

## 2. 方案总览

构建一条异步 `Media Ingest` 流水线：

`URL 输入 -> 内容提取 -> 总结生成 -> 质量门禁 -> 写入 OpenViking`

入口支持两类：

- **Agent 主动触发**（chat 工具调用）
- **Tracking 周期触发**（URL 型 target 轮询）

输出统一沉淀到 OpenViking 日记（Markdown），前端 `Aelinの日记` 直接读取。

## 3. 具体采用方式

### 3.1 抓取层（多平台统一）

- 用 `yt-dlp` 作为多平台统一抽取入口（YouTube/B 站/抖音/其他站点 URL）。
- 保留平台特化接口（后续可给 B 站等做专门增强）。
- 所有 URL 统一做协议与参数安全校验。

### 3.2 内容提取层（三段式回退）

按可靠性从高到低：

1. 手动字幕
2. 自动字幕
3. Whisper ASR（下载音频后转写）
4. 仅在前三步失败时，使用 description fallback（并打低置信度标签）

### 3.3 总结层（结构化输出）

总结模型必须输出结构化字段，再渲染成 Markdown：

- `title`
- `overview`
- `key_points[]`
- `evidence[]`
- `actions[]`
- `confidence`
- `source_type`（subtitle/asr/description）

### 3.4 质量门禁（防脏写）

写入日记前做规则+模型双门禁：

- 规则门：长度、重复度、来源类型、异常内容检测
- 置信度门：低于阈值不写正式日记，转为 `pending_review`

### 3.5 记忆写入与检索

- 复用现有 `openviking_bridge.append_insight` 作为统一落盘能力。
- 保留 `path / confidence / source_type / query` 元信息，支持后续检索与溯源。

## 4. 最终效果会如何

用户输入一个视频 URL 后，系统可自动完成：

1. 识别并抓取可用内容（字幕/音频/描述）
2. 生成结构化、可读总结
3. 通过质量门禁后写入 `Aelinの日记`
4. 在 Diary 页面可检索、可追踪、可引用

同时对 agent 来说，这些总结会成为可复用长期记忆，后续回答更稳定。

## 5. 相比当前的提升

1. **能力范围提升**：从“文本为主”扩展到“视频语义可用”。
2. **质量可控**：引入置信度与门禁，显著降低错误记忆写入概率。
3. **架构更稳**：重任务异步化，不阻塞聊天主流程。
4. **运维可观测**：每个任务有状态、来源、耗时、失败原因，便于排障。

## 6. 借鉴 Youwee 的部分

本方案明确借鉴了 Youwee 的工程经验，但只吸收核心能力，不引入下载器产品形态：

### 借鉴点

1. **多平台统一抽取思路**：以 `yt-dlp` 作为跨平台入口。
2. **提取链路优先级**：字幕优先，ASR 兜底，描述最后回退。
3. **Cookie/Proxy 接入**：提高受限内容抓取成功率。
4. **安全边界**：URL 校验、参数注入防护、`--` 分隔策略。

### 不直接搬运部分

1. 下载队列与媒体后处理 UI
2. 字幕编辑工作台
3. 下载器导向的产品交互逻辑

## 7. 实施分期（建议）

### Phase 1（MVP）

- 新增 URL ingest 异步任务
- 实现字幕提取 + 基础总结
- 写入 OpenViking insight（含 source_type/confidence）

### Phase 2（质量增强）

- 接入 Whisper fallback
- 上线质量门禁（pending_review）
- 增加失败重试与错误分类

### Phase 3（追踪融合）

- 与 tracking URL target 自动联动
- 支持增量总结与版本对比
- 输出 agent 可消费的摘要索引

## 8. 关键验收标准

1. 给定 20 条跨平台 URL，成功生成可读总结比例达标。
2. 低质量来源（仅 description）不会直接写入正式日记。
3. chat 主流程在 ingest 执行时无明显阻塞。
4. Diary 页面可稳定检索新增条目，并显示来源与置信度。
