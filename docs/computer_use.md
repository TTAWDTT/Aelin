# Aelin Computer Use 体系文档（清晰版）

## 1. 一句话目标
Aelin 不是“只会看图”的助手，而是一个会自动选择模式的系统：
- 简单问题：直接 `Chat` 快速回答。
- 复杂任务：进入 `Computer Use`，读屏、规划、执行、复核。

## 2. 当前链路（已实现）
1. 手动截图输入：用户点击相机，截图直接发给 Aelin 做图像理解。  
2. Agent 自主读屏：`screen_get` 已进入 Agent Loop，可在需要时主动读取当前屏幕。  
3. 普通文本对话：不需要工具时走快速对话路径。  

结论：现在支持“用户发图”和“Agent 主动读屏”两种入口，并行存在。

## 3. Aelin 如何自动切换
按这个顺序判断：
1. 用户是在“问解释”还是“要操作”？  
- 例：`这张图写了啥？` -> 走图像理解（不操作环境）。  
- 例：`帮我点开官网并登录` -> 走 Computer Use。  
2. 是否需要实时状态？  
- 如果要“现在去做动作”，先读当前屏幕（`screen_get`）。  
3. 是否有风险动作？  
- `发送/提交/支付/删除` 必须二次确认。  

## 4. 工具边界（必须遵守）
### `screen_get`
- 作用：读屏和状态确认。  
- 特性：只读，不产生副作用。  

### 手动截图输入
- 作用：给模型看一张具体图片并回答问题。  
- 特性：适合分析，不等于“当前实时屏幕状态”。  

## 5. 执行流程（Computer Use）
`读屏 -> 计划 -> 执行一步 -> 再读屏复核 -> 下一步`

失败策略：
1. 单步失败先重试。  
2. 连续失败则降级为说明原因 + 给用户可执行建议。  
3. 用户随时可中断。  

## 6. 分阶段推进（接下来）
### 阶段 A（已完成）
- 截图主链路。
- `screen_get` 接入 Agent Loop。

### 阶段 B（下一步）
- 浏览器状态工具（如 `browser_state_get`）。
- 浏览器执行工具（如 `browser_use`）。

### 阶段 C（收口）
- 安全边界、审计日志、失败恢复统一化。

## 7. 验收标准（实用版）
1. 读屏任务 10 次中成功 >= 8 次。  
2. 高风险动作确认拦截率 = 100%。  
3. 出错时能给出明确失败原因和下一步建议。  
4. 全链路可追踪：看得到“计划-工具-结果”。
