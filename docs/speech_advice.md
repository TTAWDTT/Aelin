# Aelin 答辩介绍策略指南

## 一、核心原则

### 1. 差异化定位——第一句话就要不同

**错误示范：**
> "我们做了一个基于大语言模型的 AI 聊天助手。"

评委听过几十个类似开场，会立刻失去兴趣。

**正确示范：**
> "现有 AI 助手用完即弃，没有记忆。Aelin 让 AI 拥有持续积累的个人记忆，用长期追踪的证据回答问题。"

一句话传达差异：**ChatGPT 是搜索引擎的升级，Aelin 是个人信息管理的升级。**

### 2. 技术深度 > 功能数量

不要试图在有限时间内展示所有功能。评委关心的是：
- 你解决了什么真实问题？
- 技术方案有什么创新点？
- 系统完成度如何？

挑 3-4 个核心亮点讲透，远好于 10 个功能一笔带过。

### 3. 演示优于讲述

能现场跑的就现场跑，能看到效果的就看效果。准备一条完整的演示路线，避免临场翻找功能。

## 二、亮点优先级排序

根据计算机设计大赛的评审维度（创新性、技术难度、完成度、实用性），建议按以下优先级展示：

### 第一梯队（必讲）

| 亮点 | 对应评审维度 | 讲解要点 |
|------|-------------|---------|
| Agent Loop + 工具调用系统 | 技术难度 | 多轮自主决策、读写分离并行、策略约束、trace 可审计 |
| 三层记忆模型 | 创新性 | Session / Preference / Evidence 三层、跨会话持久、证据优先 |
| 多源联网搜索 | 完成度 | 7 源并行、打分去重、三级回退抓取、不依赖商业 API |

### 第二梯队（有时间就讲）

| 亮点 | 对应评审维度 | 讲解要点 |
|------|-------------|---------|
| 追踪系统 | 实用性 | 定时调度、变更检测、自动写入记忆 |
| 桌面宠物情绪引擎 | 创新性/展示力 | 四维情绪模型、感知用户状态、视觉直观 |

### 第三梯队（被追问时用）

| 亮点 | 场景 |
|------|------|
| 12 种数据源连接器 | 被问到多源接入能力时 |
| Fernet 可选加密 | 被问到数据安全时 |
| Electron 桌面壳打包 | 被问到部署方式时 |

## 三、演示路线设计（建议 5 分钟以内）

### 路线 A：标准路线（推荐）

```
第 1 分钟  开聊 ——
           打开 Aelin，问一个需要联网的时事问题
           展示：流式回答 + 工具调用过程 + 多源搜索聚合

第 2 分钟  记忆 ——
           紧接着问一个关联问题（不重复上下文）
           展示：Aelin 记住了之前的对话 + 引用历史证据

第 3 分钟  追踪 ——
           展示一个已配置好的追踪目标
           展示：自动变更检测 + 快照对比 + 变更写入记忆

第 4 分钟  设备感知 ——
           让 Agent 调用 device 工具
           展示：获取设备状态 / 进程列表

第 4.5 分钟 桌面宠物 ——
           展示宠物情绪随用户状态变化
           展示：从 calm → flow → deep-focus 的情绪转换

第 5 分钟  收尾 ——
           回到架构图，总结 Aelin 的技术体系
```

### 路线 B：网络不好时的备案

提前准备：
1. 一组本地缓存好的搜索结果（避免现场联网失败）
2. 已有对话历史的 workspace（直接展示记忆效果）
3. 已有变更记录的追踪目标（直接展示快照对比）
4. 录屏备份（最坏情况播放录屏）

## 五、评委高频提问预判与应对

| 可能的问题 | 建议回答方向 |
|------------|------------|
| 和 ChatGPT / Kimi / 豆包有什么区别？ | 它们是无状态问答工具，没有长期记忆和主动追踪。Aelin 的每次对话都在积累证据，越用越了解你。 |
| 为什么不直接用商业搜索 API（Google/Bing API）？ | 自建 7 源搜索：零成本、不受 API 限额约束、有三级回退保证可用性。也验证了我们对搜索聚合的工程能力。 |
| Agent Loop 会不会失控（死循环、过度调用）？ | 有完整策略引擎：轮次上限 + 调用计数 + 读写分离 + 单轮/总超时双保险 + 无进展自动终止。 |
| 数据安全怎么保证？ | 全部数据本地存储，不上传任何第三方。敏感字段 Fernet 加密，密钥用户自控。 |
| 为什么用 SQLite？ | 个人场景优先零依赖部署。架构已预留抽象层，可平滑迁移 PostgreSQL。 |
| 桌面宠物和 AI 助手有什么关系？ | 宠物是 Agent 状态的可视化——它的情绪映射用户当前的工作状态（专注/空闲/疲劳），让冷冰冰的 AI 有了温度。 |
| 多源搜索的结果质量怎么保证？ | 每个源独立打分（provider 权重 + 排名 + 关键词匹配），URL 去重，Top K 结果做内容抓取验证，有 CAPTCHA/屏蔽页检测。 |
| 记忆会不会无限膨胀？ | 有 recency decay 机制，老旧未引用项权重递减。用户可手动删除笔记和调整追踪边界。 |

## 六、注意事项

### 命名
代码中有大量 `MercuryDesk` 残留（环境变量前缀、数据库名等）。答辩时统一说 **Aelin**。如果被注意到，解释为"项目演进过程中的重命名，技术债正在清理"。

### 不要展示太多连接器
12 种数据源全讲会冗长。挑 2-3 个有代表性的：**GitHub + RSS + 邮箱**，其余一笔带过。

### 强调"证据链"
每次演示时都指出 Aelin 的回答附带了来源引用。这是和普通 AI 的根本区别——**有据可查，而非凭空生成**。

### 语速与节奏
- 技术细节讲慢一点，确保评委跟上
- 演示环节提前排练，确保流畅
- 留 1-2 分钟给评委提问

### 团队分工
如果是团队答辩，建议：
- 一人负责开场 + 愿景 + 架构总览
- 一人负责现场演示 + 技术细节
- 提问环节谁熟悉谁答，不要互相推诿
