# Aelin Computer Use v1 技术规格（2026-03-03）

## 1. 目标与原则
- 目标：让用户在尽量少配置下，完成常见 computer use 场景（先读屏，再半自动执行）。
- 原则：先可用、再自动；先低风险、再高风险；默认可解释、可审计、可中断。
- 本期核心：`screen read` 必须稳定，浏览器操控作为第二阶段能力。

## 2. 本期范围（v1）
### 2.1 必做
- 聊天输入框保留一个相机按钮，点击后自动截图。
- 截图进入 Aelin 分析链路，输出：页面理解、用户意图猜测、可执行建议。
- 结果按普通聊天流程进入记忆系统；不新增“截图专用记忆入口”。
- 截图触发轮次默认不写前端 chat diary（避免噪声日志）。
- 该链路属于 **Chat 视觉推理**（图片直达模型），**不要求调用 `screen_get` 工具**。

### 2.2 次阶段（v1.1）
- 浏览器只读能力：DOM/可访问树快照 + 页面摘要。
- 浏览器可执行能力：点击、输入、滚动等基础动作（高风险动作强制二次确认）。

## 3. 用户交互流
1. 用户点击相机按钮。
2. 客户端请求桌面端截图接口。
3. 后端将图片作为 `images[]` 输入喂给模型（Chat 视觉链路）。
4. Aelin 返回「我看到了什么 + 我建议你下一步做什么」。
5. 用户选择：继续对话 / 执行建议动作（后续阶段）。

## 3.1 模式路由规则（新增）
- 若用户目标是“解释图片/提问图片内容”：走 `chat_vision(images)`。
- 若用户目标是“请你代我操作电脑/浏览器”：走 `computer_use`。
- `screen_get` 仅在 `computer_use` 的 `sense/verify` 阶段调用，用于获取实时状态。
- 用户上传旧截图但要求当前实时操作时，系统应补一次 `screen_get` 复核后再执行。

## 4. 架构与接口（建议合同）
### 4.1 Desktop
- `POST /v1/device/screen/capture`
- 返回：`{ image_base64, width, height, captured_at, source_display }`

### 4.2 Backend
- `POST /api/v1/aelin/device/screen/capture`
- `POST /api/v1/aelin/tools/screen-read`（内部可由 agent loop 调用）

### 4.3 Tool 定义
- 工具名：`screen_get`（Computer Use 专用）
- 入参：`purpose`（可选，任务意图）、`region`（可选，局部坐标）
- 出参：
  - `screen_summary`
  - `detected_targets[]`
  - `suggested_actions[]`
  - `risk_level`（low/medium/high）

## 5. 安全与策略
- 敏感动作（登录、支付、删除、发送）一律二次确认。
- 默认域名白名单 + 本地应用白名单；未知目标仅允许只读。
- 全链路审计：保存动作计划、确认记录、错误码、耗时。
- 失败兜底：任一步超时或识别不稳，回退到“只读解释模式”。

## 7. 里程碑与验收
- M1（3-5 天）：截图 + `screen_read` 打通，可稳定返回建议。
- M2（3-5 天）：浏览器只读能力上线，可对网页任务给出结构化建议。
- M3（5-7 天）：浏览器基础动作上线，敏感操作具备二次确认与审计。

验收标准：
- 10 个真实任务中，读屏理解可用率 >= 80%。
- 任意高风险动作均不可绕过确认。
- 失败场景可回退且不导致连锁误操作。
