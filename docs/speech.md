# Aelin 答辩演讲稿

> 预计时长：8-10 分钟（可根据实际要求删减）

---

## 开场（1 分钟）

各位评委老师好，我今天介绍的项目叫 Aelin。

在开始之前，我想先问一个问题：大家平时用 AI 助手的时候，有没有遇到过这样的情况——你上周刚和它聊过一个话题，这周再问，它完全不记得了？你得把所有背景重新说一遍？

这是目前几乎所有 AI 助手的通病：**它们是无状态的**。每次对话都从零开始，用完即弃，没有记忆，没有积累。

Aelin 要解决的，就是这个问题。

**Aelin 不是又一个聊天机器人。它是一个拥有长期记忆、能持续追踪你关心的事物、用积累的证据来回答问题的个人 AI 系统。**

如果用一句话概括它和 ChatGPT 的区别：ChatGPT 是搜索引擎的升级，Aelin 是个人信息管理的升级。

---

## 一、核心问题与产品定位（1 分钟）

我们观察到，一个真正有用的个人 AI 助手，至少需要解决三个问题：

**第一，记忆的连续性。**
用户的需求不是孤立的，而是随时间演进的。今天关注 NBA 季后赛，下周可能还想知道后续战况。AI 应该记住这些线索。

**第二，信息的可追溯性。**
大语言模型会"幻觉"，会编造事实。当 AI 给出一个回答时，用户需要知道——这个信息从哪来的？有没有证据？

**第三，信息的主动获取。**
用户不应该每次都手动去查。AI 应该能主动追踪你关心的信息源，在有变化时告诉你。

围绕这三个问题，Aelin 构建了四个核心能力：**Chat 聊天入口、长期记忆系统、联网搜索引擎、追踪与变更检测系统**。

---

## 二、系统架构总览（1 分钟）

Aelin 采用 Monorepo 架构，分为四层：

**底层是数据层**——SQLite 数据库加上本地文件系统，存储用户数据、对话记录、记忆和追踪快照。

**中间是服务层**——基于 Python FastAPI 构建，包含 Agent 决策引擎、多源搜索服务、追踪调度器、记忆桥接等核心模块。

**上层是接入层**——React 19 构建的 Web 前端，提供聊天、追踪、设置等交互界面。

**最外层是桌面壳**——Electron 封装，支持打包为 Windows 桌面应用，还集成了一个有趣的桌面宠物系统。

整个系统支持 12 种数据源接入，包括 GitHub、Gmail、RSS、微博、Bilibili 等，通过统一的 Connector 协议标准化消息格式。

## 三、核心技术亮点（4 分钟）

接下来我重点介绍 Aelin 的四个核心技术创新点。

### 3.1 Agent Loop：多轮自主决策引擎

Aelin 的聊天不是简单的"用户提问、调一次 API、返回结果"。

它的内核是一个 **Agent Loop——自主决策循环**。工作流程是：

1. 用户提问后，LLM 首先判断：这个问题我能直接回答，还是需要调用工具获取更多信息？
2. 如果需要工具，LLM 会从六大工具族中选择——上下文检索、日记查询、用户画像、追踪系统、设备状态、联网搜索。
3. 每个工具调用都要经过**策略引擎**的审批：是否在允许列表中？调用次数是否超限？是读操作还是写操作？
4. 工具执行结果回注到对话上下文，LLM 继续推理，决定是给出答案还是继续调用工具。
5. 这个循环持续进行，直到得出答案，或者触发终止条件——超过轮次上限、超时、或连续两轮无进展。

这里有两个关键的工程设计：

**一是读写分离并行**。读工具——比如检索上下文、搜索日记——可以安全地并行执行，我们用线程池同时跑，降低延迟。写工具——比如创建追踪目标、写入笔记——则严格顺序执行，防止副作用冲突。

**二是双超时保护**。单轮 LLM 调用有 10 秒超时，整个 Agent Loop 有 12 秒总超时。再加上轮次上限和调用计数，确保系统不会失控。

每一轮循环都有完整的 trace 记录，包括工具名称、参数、状态、结果和延迟，可以回溯审计。

### 3.2 三层记忆模型

Aelin 的记忆系统是我们区别于所有"套壳 ChatGPT"项目的根本所在。

我们设计了三层记忆模型：

**第一层：Session Memory——会话记忆。** 当前对话的上下文，和普通 AI 一样，关闭窗口就结束。

**第二层：Long-term Preference——长期偏好记忆。** 用户关注什么领域、常问什么类型的问题、注意力模式是怎样的——这些跨会话持久存储。

**第三层：Signal Evidence——信号证据记忆。** 每一条信息都带有时间戳和来源链接。不是模糊的"我记得你说过"，而是"2 月 15 日你追踪的 GitHub 仓库更新了 v2.0，变更记录在这里"。

记忆的更新遵循四条规则：
- 用户显式输入优先级最高
- 在活跃追踪边界内的信号权重更高
- 老旧未引用的项权重随时间递减
- **证据优先**——有信号证据支撑的回答，优先于纯推理猜测

底层我们通过 OpenViking 兼容的文件系统结构持久化，异步写入队列保证不阻塞主线程。

### 3.3 自建多源联网搜索引擎

很多 AI 产品的联网搜索依赖 Google API 或 Bing API，有调用限额，还要付费。

Aelin 完全自建了搜索引擎，**并行查询 7 个搜索源**：Bing HTML、DuckDuckGo Lite、DuckDuckGo Instant、Google News RSS、Reddit、Hacker News、Wikipedia。

搜索流程分三步：

**第一步，并行查询。** 最多 6 路并发，向 7 个源同时发起请求。

**第二步，打分去重。** 每个结果按来源权重、排名位置、关键词匹配度综合打分。URL 和标题去重，合并排序，取 Top K。

**第三步，内容抓取。** 对排名靠前的结果做全文摘要抓取。这里我们设计了**三级回退机制**：
- 首先尝试直接 HTTP 请求，解析 HTML 提取正文
- 如果命中反爬或需要 JavaScript 渲染，回退到 Reader API
- 最后兜底用 Playwright 无头浏览器实际渲染页面

系统还内置了智能检测——能识别 CAPTCHA 页面、"请开启 JavaScript"提示、和各类反爬屏蔽，自动选择最合适的抓取策略。

### 3.4 追踪与变更检测系统

Aelin 不仅在你提问时帮你搜索，还能**主动帮你盯着你关心的东西**。

用户可以设定追踪目标——比如某人的微博、某个 GitHub 仓库、某个 RSS 源。系统会按设定的频率自动检查，与上一次快照对比，检测到变更后自动生成变更记录，评估重要性，并写入长期记忆。

下次你聊到相关话题时，Aelin 不需要重新搜索——它已经知道了，而且能告诉你"上次检查是什么时候，变化了什么"。

这就是从"被动问答"到"主动感知"的进化。

## 四、桌面宠物与情绪引擎（0.5 分钟）

最后分享一个我们觉得很有趣的功能——桌面宠物。

AI 助手通常是冷冰冰的对话框。我们给 Aelin 加了一个桌面宠物，它不是装饰，而是 **Agent 状态的可视化映射**。

宠物有一个独立的情绪引擎，用四个维度来描述状态：愉悦度、能量值、专注度、紧张度。引擎会感知用户当前的工作状态——你在专注写代码，它会进入 flow 状态安静陪伴；你的 CPU 飙到 90%，它会显得紧张；深夜了还在工作，它会犯困提醒你休息。

这让一个技术系统有了温度。

---

## 五、技术总结（0.5 分钟）

总结一下 Aelin 的技术体系：

- **Agent Loop**：多轮自主决策，读写分离并行，策略约束可控
- **三层记忆**：会话 + 偏好 + 证据，跨会话持久，证据优先
- **自建搜索**：7 源并行，打分去重，三级回退抓取
- **追踪系统**：定时调度，变更检测，自动记忆写入
- **桌面宠物**：四维情绪模型，感知用户状态

整个系统使用 FastAPI + React 19 + Electron 构建，支持 12 种数据源接入，全部数据本地存储，不依赖任何商业 API。

---

## 结语（0.5 分钟）

Aelin 的名字来自古诺斯语，意思是"火炬"。

我们希望它不只是一个回答问题的工具，而是一个真正能陪伴用户、持续积累、帮助思考的 AI 伙伴。它记得你关心什么，主动帮你追踪变化，每一个回答都有据可查。

我们相信，**有记忆的 AI，才是有价值的 AI**。
