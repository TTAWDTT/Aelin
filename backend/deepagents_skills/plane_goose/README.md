# Goose Plane Skill for DeepAgents

本技能为后续接入 goose 类 plane 预留，介绍其基本使用模式。

## 能力概览

- 作为针对特定站点或 API 的浏览 / 交互 plane。
- 适合需要多步调用、复杂导航的长链路任务。
- 可以在一个站点内执行多步操作（如登录 → 搜索 → 打开详情页 → 提取信息）。

## goal 模板示例

对于 goose plane，goal 应该尽量「站点 + 操作 + 目标」三要素齐全：

- 「在某某电商网站中，搜索‘机械键盘’，筛选 500 元以内，按照销量排序，提取排名前 10 条商品的名称和价格。」
- 「登录某内容管理后台，找到今天新建的文章列表，列出标题和作者。」
- 「在某财经网站中，导航到今日要闻页，总结 3～5 条与 A 股相关的重点消息。」

## 使用约定

1. 与 browser plane 一样，通过 `plane` 工具调用，区别在于：
   - `plane = \"goose\"`（或后续约定的具体名字）。
   - `action` 仍为 `delegate` / `status` / `continue` / `close`。

2. 在构造 `goal` 时，应尽量清晰：
   - 指定要使用的站点或系统（如具体域名或系统名称）。
   - 描述需要完成的主要操作步骤（搜索 / 筛选 / 打开详情等）。
   - 指出期望的结果形式（列表 / 表格 / 概要说明）。

3. 避免在 goose plane 中重复执行大语言模型可以直接完成的纯文本推理任务：
   - goose plane 更适合需要真实网络交互、复杂状态管理的任务。
   - 单纯的「根据已有文本总结 / 改写」应优先在主模型中完成，而不是委派给 goose plane。

4. 当任务需要多轮交互时：
   - 通过 `status` / `continue` 轮询任务进度。
   - 根据 `state` 字段判断是继续执行、等待用户操作还是已经完成。
